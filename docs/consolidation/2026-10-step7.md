# Step 7: opt-in grading changes

Status: design for AC review, 26 October 2026. This is the grading stage in
[the consolidation audit](../audit-2026-10/README.md), §5b: P5, P15,
P21.3 and PY-10. It follows the standalone-worker work (P13). The audit's
older B1 decision allowed particular extraction fixes to become defaults;
AC's step-7 decision is **different**: each change below starts as an
independent author opt-in. A later major release may change defaults only
after its own course comparison and AC decision.

Step 7 changes math-exercise grading through ctm-checkers, except for
math-exercise's page and rendering code. PY-10 is in py-exercise's existing
runner and Lua filter. STACK keeps its own answer tests and its grades do
not change. No step-7 option changes a custom checker implicitly.

## 1. Author contract and compatibility

The public opt-ins are separate flat keys, not one grading preset. Authors
may set each Boolean under `math-exercise:` or `py-exercise:` in project
or page metadata, or override it with the same `#|` key on an exercise.
The exercise value wins, including an explicit `false` over a project
`true`. ctm-libs' existing settings reader resolves project/page keys;
the components resolve each exercise override and validate Boolean values
at render time. All new Boolean defaults are `false`.

```yaml
math-exercise:
  decimal-comma: true
  float-equivalence: true
py-exercise:
  keyword-families-v2: true
```

~~~qmd
```{math-exercise}
#| label: scalar-example
#| mode: equivalent
#| decimal-comma: false
Find the value of _[7/2].
```
~~~

| Option | Applies to | Opted-in change |
|---|---|---|
| `single-fraction-v2` | `form: single_fraction` | Judge the written fraction, accepting equivalent numerator/denominator representations without requiring SymPy's exact `together()` output. A top-level sum of fractions still fails the requested form. |
| `factored-form-v2` | `form: factored` | Accept valid factorizations differing by units, signs and factor order; require each polynomial factor to be irreducible in the documented domain. |
| `lowest-terms-v2` | `form: lowest_terms` | Inspect written integer fractions before SymPy reduces them, including parentheses around numerator or denominator; `84/(126)` and `(84)/126` fail. |
| `reject-before-form` | an exercise with `reject:` and `form:` | After mathematical equivalence, apply an exact rejection before the form check, so an explicitly rejected response cannot earn form credit. |
| `forbid-calls` | built-in math modes | A comma-separated list of student-call names to reject before evaluating the answer. The empty default keeps the old behavior. Authors may list `diff, integrate`; the student legend stops advertising these as general answer syntax. |
| `euler-e` | parsed math answers | Treat a written lowercase `e` as Euler's constant. If `vars:` declares `e`, fail the build for this opt-in rather than guessing which meaning the author intended. |
| `float-equivalence` | `mode: equivalent` with a float-containing key | Use bounded numerical checks around symbolic equivalence, as specified in §3. |
| `decimal-comma` | a single scalar field with a numeric key on a comma-locale page | Accept one decimal-comma literal such as `3,5` as `3.5`, including in `mode: equivalent`. §4 defines the exclusions. |
| `keyword-families-v2` | py-exercise `forbidden-keywords` | Extend the AST rule families for async and starred forms as in §5. |

MATH-19's `assess_basis` helper is author-supplied checker code, not a
built-in exercise mode. Its independent opt-in is a new
`assess_basis(..., numeric_zero=True)` argument. It classifies exact
numeric `0.0` as zero for colouring and feedback; it is not an
approximate-zero tolerance. The default preserves existing checker calls.

An absent or false option preserves the previous parse, verdict, score and
feedback. Any option that affects grading enters the resolved exercise
source/revision hash, the variants approval hash, and the saved-result
invalidation input. An author changing an opt-in must review affected
variants again; a student's old grade is offered as history, not silently
restored as current.

## 2. P5: form, rejection and allowed calls

The form tests operate on the learner's written parse tree. Normalizing a
tree to a canonical SymPy string before testing loses the distinctions
that `single_fraction`, `factored` and `lowest_terms` ask about. The
new tests therefore use written structure first and symbolic calculation
only to check equivalence and irreducibility. In particular, the
`single_fraction` examples `(2x+1)/(x^2+x)` and
`(2x+2y)/(2xy)` pass if mathematically equivalent to the key, while
`1/x + 1/y` still fails that form. For `factored`, include
`-x(2-x)(x+2)` and `(-x-1)(-x-2)` in the reviewed golden table.
An unsupported factor domain must yield a clear author diagnostic rather
than silently claiming the answer has the wrong form.

`reject-before-form` changes only precedence after the answer has been
found equivalent. A reject match returns `rejected` with zero credit;
otherwise the selected form check and its existing `form-credit` rule
run. A genuinely wrong mathematical answer remains `wrong`. The
`forbid-calls` check examines named direct or nested calls in learner
text before SymPy evaluation; it does not ban the same names as declared
variables or change the teacher's key. Its diagnostic names the call.
Malformed call names in the author list stop the render.

The `euler-e` rule changes both answer-key and learner parsing under the
opt-in. The `vars: e` conflict is checked at render time; other variable
names and the existing uppercase `E` behavior stay unchanged.

## 3. P15: bounded equivalence for float keys

The current `mode: equivalent` path calls `simplify(student - key)`
without a bound. The F-67 fixture has taken about 40 seconds and consumed
large memory; a float key can also leave a roughly 1e-16 residual and
reject an intended equivalent answer. The opt-in path must:

1. Reject a clear numerical mismatch before calling `simplify`. Probe
   deterministically from the key, learner text and declared variables,
   on at least eight distinct finite real points that are valid for both
   expressions. Skip singularities and non-real results; insufficient
   valid points are inconclusive, never proof of equality or inequality.
   Include non-integer and differing-magnitude points. Store no random
   or Python-hash-seed state in a grade.
2. Keep acceptance of keys without SymPy `Float` symbolic. For a
   float-containing key, allow
   numerical acceptance only when all valid probes agree within a
   documented relative bound of `1e-9 * max(1, |student|, |key|)`, with
   no probe near an excluded singularity or non-finite value. Record the
   reason as `float-key-tolerance` in test output; this is a bounded
   heuristic for self-study, not a claim of symbolic identity. Include
   functions that coincide at ordinary sample points in the adversarial
   corpus; such cases must be classified as mismatched or inconclusive.
   Fixed samples alone cannot prove equality for arbitrary functions.
3. Put a real deadline around symbolic work, not merely a
   `count_ops` check followed by unbounded `simplify`. The first
   implementation should target five seconds per opted-in check, subject
   to a measured corpus showing that ordinary checks fit. P13's worker
   must be able to stop the over-budget request and restore a usable page
   runtime. If that contract cannot be demonstrated, hold P15 rather
   than ship an unbounded call.
4. Return `undecided` with no score when neither path can decide within
   the bound. The UI says "Could not decide; try another form" in the
   page language. It does not mark the answer wrong, average a zero into
   a multi-field grade, save a grade, or approve a teaching variant.
   Authored tests that expect a grade fail on `undecided`.

The result contract and feedback/store adapters must represent
`undecided` explicitly; they must not turn it into `error` or
`wrong: 0`. STACK may share the result type but continues to emit only
its existing statuses. The exact five-second value is a design target:
if the benchmark needs a different bound, record the measurements and
seek AC review before changing the contract.

## 4. P21.3: decimal comma

With `decimal-comma: true`, use the resolved page language from
ctm-libs. For `nb`, `nn`, `de`, `sv` and `da`, normalize one
standalone decimal literal between digits (`3,5` to `3.5`) only when
the exercise field is scalar and its resolved answer key evaluates to a
finite number. English pages keep the old syntax. The option applies to
`mode: equivalent` as well as `numeric`; it does not rewrite commas
inside vectors, lists, matrices, tuples, function arguments or a larger
expression, and it does not accept thousands separators. `3,5` means
three and a half, not three thousand five hundred. The input help states
the accepted form in the page language. Author keys retain dot-decimal
syntax. Browser checks, authored tests, native parity and variant
approval use the same rule for candidate learner responses.

## 5. PY-10: forbidden keyword families

With `keyword-families-v2: true`, py-exercise's AST rule maps `for`
to `For|AsyncFor`, `with` to `With|AsyncWith`, `try` to
`Try|TryStar`, and `yield` to `Yield|YieldFrom`. The ordinary forms
keep their current verdicts. This is an author restriction for teaching,
not a security boundary: indirect calls, imports and dynamic execution
are not made safe by this feature.

For any page that supplies a Python keyword whose AST form is unsupported
by `forbidden-keywords`, the Lua filter stops the render with the name,
exercise label and list of supported keyword names. Non-keyword names
remain valid function/method restrictions (for example `sorted` or
`eval`). This is AC's explicit build-diagnostic decision; it applies
even before the new grading option is enabled, whereas the extra AST
rejections require the opt-in. The same resolved rule set and option enter
py-exercise's saved-result source hash. Native fixture checks and the
browser runner share one table of supported names and AST families; a
mismatch fails CI.

## 6. Repository sets and release gates

Prepare small stacked sets; AC merges each with merge commits after the
proposed merged tree equals the CI-tested head:

| Set | Component work | Umbrella acceptance |
|---|---|---|
| S7a, P5 | ctm-checkers' math form/reject/parser helpers; math-exercise option plumbing, `assess_basis` opt-in, documentation and goldens; ctm-libs catalogue only for new user text | Pin reviewed heads and test the F-67-independent P5 examples, no-AI/exam profiles and the full legacy corpus. |
| S7b, P15 | P13 deadline/restore proof; ctm-checkers bounded path and `undecided` result; math-exercise feedback, store and UI handling; localized message | Exercise the F-67 reproducer, timeout and worker restart, adversarial numerical cases, mixed component page and all authored/teacher tests. |
| S7c, P21.3 | ctm-checkers scalar normalization; math-exercise page-language and help integration; same rule in authored/variant tooling | Test all six catalogue languages, comma and separator counterexamples, course parity and saved/approval invalidation. |
| S7d, PY-10 | py-exercise Lua validation and runner AST families, docs and tests; update locale messages only where needed | Pin the reviewed py-exercise head and run its native/browser cases and the combined course gate. |

Each set's umbrella PR is the combined gate. Pins select reviewed heads,
then the final umbrella pin uses the merged component commits. For every
set run component source and built-wheel tests, Pyodide 0.27.2/0.28.3
parity, authored question tests, full rendered comparisons of examples,
STACK, ctm-demo and Ingmat3a, and the browser mixed page. Preserve
every legacy unopted verdict and numeric score. Record each intended
opt-in change by case ID and reason in a reviewed expected-diff file;
the comparison rejects any unexplained grade, score, feedback, source
or rendered difference. Golden tests cover the opt-in and its false
control side by side, including the exact P5 and F-67 witnesses. Do not
put raw run logs in a repository.

No set edits the Maxima backend or changes STACK answer-test defaults.
No tag, deployment, course-main change or branch deletion belongs to
this design; AC handles PR merges and any later release.
