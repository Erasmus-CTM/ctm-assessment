## 1. STACK integration: what is left

Inventory at the freeze. Evidence is in the register (§S items).

1. **The native backend is not packaged.**
   - The package pins ctm-stack `e8437f1`, where `ctm-stack.lua` stops on `cas: maxima`.
   - ctm-stack `main` (`7b68ec8`) is 23 commits ahead. It adds the Maxima cards and Python PRT compiler (#39), native PythonChecker nodes (#40) and the host-SymPy identity check (#41).
   - ctm-checkers `4cff6aa` already ships the native side (#42–#44), so the pins are skewed.
2. **The Maxima runtime (`runtime-v3`, stack-wasm-maxima) is not in any asset lock.**
   - Authors stage it by hand (`CTM_STACK_NATIVE_PACKAGE`).
   - The online build needs the same locking and provenance as the other assets: runtime-v3 digest, licences and source offer, compression sidecar policy (stack-wasm-maxima follow-up F-7).
3. **No Maxima tests in the umbrella.** The browser and parity harnesses cover only SymPy. SymPy vs Maxima parity on the shared corpora was never run (#93: "fresh full native Maxima/STACK parity" unverified).
4. **STACK's private worker.** Both backends start their own unpublished worker. Step 5 phase 2 (STACK on the page worker) is **not needed for 1.0** under D3/D5, because STACK is online only, but local mode must refuse STACK explicitly. Today only boards are refused.
5. **Duplication:**
   - `variants-review.py` ×2 (M13/B4);
   - ctm-stack's own MathJax loader with a `mathjax@3.2.2` CDN fallback;
   - ctm-demo `assets/stack/figure-common.js` bridge listener.
6. **Documentation:**
   - no STACK activity in `docs/authoring.md`;
   - no build-time requirements for `cas: maxima` (Node, runtime staging);
   - the ctm-stack CHANGELOG still reads "0.4.0 (step 6, for review)" and says Maxima is a diagnostic;
   - the ctm-checkers README still says "stack-sympy".
7. **Open component work:**
   - ctm-stack plan remainders: M4e seed import, M4g compatibility/locales, M4h distribution;
   - stack-wasm-maxima follow-ups F-1, F-7, F-8, F-11, F-12;
   - the precompiled-STACK, snapshot and interrupt runtime items;
   - the long GC stress run to repeat after packaging changes staging;
   - the upstream STACK security report (author pure-function bypass) is prepared but not sent;
   - issue stack-wasm-maxima#14 (handoff).
8. **Branches:**
   - ctm-stack: 2 old checkpoint/handoff branches;
   - stack-wasm-maxima: 14 research branches. `evidence/maxima-oz-production` holds the only copy of the 26 Oct selection evidence, so it gets an archive tag.

## 3. The internet-free IDE (exam ZIP)

**Today:** `python-offline-website.zip`, about 126 MB. It has two Python-cell pages (`integration/offline-ide/`) and a locked bundle of 3,230 files with licences.
- CI builds and verifies it with external requests refused (`exam-site-zip.yml`).
- It is not released.
- The last green ZIP is a CI artifact that expires on 2027-01-29.
- The comparison baseline, run 40389684095, expires on 2027-01-24.

**Packaging steps for 1.0.0:**
1. **Pages:** add math-exercise and py-exercise activities to `integration/offline-ide/`, which today run only in the `p13-worker` CI fixture. Extend the offline check to cover them.
2. **Refusals:** a local/exam render with a JSXGraph board (already refused) or a STACK question (new) stops with a message naming the page.
3. **Exam mode forced** (M18): exam builds set `exam: true`, which disables AI regardless of the generated profile. Learner-answer admission fixed (A-01/M3) before any exam use.
4. **Lock:**
   - commit the complete lock metadata (or attach it to the release);
   - drop the dependency on expiring CI artifacts **before 2027-01-24**;
   - narrow the runtime binding (M19) so ordinary ctm-libs re-pins stop needing a new AC lock approval;
   - include `serve-offline.py`, `tools/offline-check.mjs` and `_extensions/ctm-assessment/**` in the workflow's path filter.
5. **Bundled server:** harden `scripts/serve-offline.py` into a shipped `serve.py`:
   - HTTP/1.1 keep-alive and digests cached at start-up (M17 remainder);
   - prefix-aware asset headers (R-03);
   - COOP/COEP/CORP, immutable caching for `_ctm-assets`;
   - optional TLS;
   - Python 3 standard library only.
   Ship it in the ZIP with the IT README.
6. **SEB:** document the required SEB settings (start URL, URL filter, clipboard, the headers the site needs). Record AC's manual checks on Windows, macOS and iOS.
7. **Release:** build the ZIP on the `v1.0.0` tag. Attach the ZIP, `SHA256SUMS`, the lock, `THIRD-PARTY-NOTICES.md` and the IT README to the GitHub release. `release.yml` today ships only the package tarball.
8. **Acceptance (A5):** extract the downloaded release asset fresh, serve it with the bundled server, load it with the network off, and run the Chromium, CEF and WebKit checks. Record the result.

## 4. Native Maxima online (D3, D4)

1. Re-pin ctm-stack to `main`, and ctm-checkers if needed, in one set. Regenerate component pins from `repos.json` (A4).
2. Lock `runtime-v3` as a release asset of stack-wasm-maxima (tag `runtime-v3`, record `maxima-runtime-v3.json`, digest in ctm-stack `native/release.json`):
