### 1.2 Rules

- **Verbatim moves.** Function bodies change only by mechanical renames (request fields for `_math_*` globals, module paths). Anything else is its own PR with a changelog entry.
- **Import-light roots.** `ctm_checkers/__init__.py` and `math_exercise/__init__.py` import no SymPy; `math_exercise/numeric.py` is stdlib-only (a test asserts `"sympy" not in sys.modules` after importing it), so `variants.py` still needs only PyYAML.
- **H2.** No import between `math_exercise` and `stack` (AST test); both may use `core`, `matrix`, `graph`, `testing`.
- **No UI in the library.** No button labels or page HTML: stack-sympy's card shell moves into its Lua (§5.2). Messages stay as today (§2.7).
- **Python ≥ 3.10.** math-exercise's build-time code runs on 3.8+ today; stack-sympy needs 3.10. CI tests 3.10, 3.12 and 3.13 (3.12/3.13 are Pyodide 0.27.2/0.28.3), so 3.10 is the tested minimum (version rule); 3.8 and 3.9 are end-of-life. Below 3.10 the entry points stop with one message naming the version.
- **`_ctm_guard` stays in ctm-libs** (`runtime/pyodide-runtime.js:115-152`): it protects the page's interpreter for py-exercise too. `browser.call` uses it when present, exactly as `_math_run` does (`math-exercise.js:517-520, 546-551`).
- **Not created now** (audit proposed them): a unified checker runner `core/custom.py` and shared `core/bounds.py`. Unifying math-exercise's runner (`exec` in a copy of the globals, prints shown) with stack-sympy's (temporary module, output discarded, signature checks, `checkers.py:83-118`) changes behaviour and belongs to H1; the two engines share no bounds today.

### 1.4 Changes from the audit's proposal (§5.1–5.5)

1. **Delivery**: not `loadPackage(<wheel URL>)` but a generated script payload installed with `globals.set` + `runPythonAsync` and zipimport — the only route that works through pyodide-interaktiv's worker proxy, on `embed-resources` and `file://` pages (§3.3, verified in Node).
2. **Home of the wheel**: ctm-checkers' own generated extension folder, pinned by the umbrella like the other components, instead of a ctm-libs resource (§3.2).
3. **No unified runner or bounds module yet** (`core/custom.py`, `core/bounds.py`): the runner would change behaviour and comes with H1; the bounds module would have nothing to hold (§1.2, §9).
4. **The `_ctm_guard` stays in ctm-libs**; `browser.call` keeps today's transaction semantics with one request global (§2.2).
5. **No UI in the library**: stack-sympy's card shell moves into its Lua; the CLI returns data (§5.2).
6. **One home for STACK question XML** (`examples/stack/`), fetched by stack-sympy's site at build time; **Python ≥ 3.10**; `math_exercise.numeric` stdlib-only for `variants.py`.
7. **Goldens in two layers**, with the math-exercise corpus captured at the runtime boundary of the umbrella's parity harness rather than regenerated (§6).
8. **stack-sympy's bootstrap and `ctm.feedback` move forward into step 2**, which removes the alias ordering risk (§5.3).

### 2.2 Browser entry and request protocol

JavaScript sets one global, `_ctm_request` (JSON text), and runs `__import__("ctm_checkers.browser", fromlist=["call"]).call("<name>", globals())`. `call`:
1. pops `_ctm_request` from the caller's namespace (as `_math_run` pops the `_math_*` names, `math-exercise.js:538`), so learner code sharing the namespace sees nothing left behind;
2. applies the call's admission rule — for math-exercise the dunder rule over `learner_strings(request)`, same `ValueError("SyntaxError: unsupported input")` (`:522-543`);
3. snapshots and restores `_ctm_guard` around the handler (`:546-551`);
4. returns `json.dumps(result)` with today's defaults (`:548`); exceptions propagate as today.

### 2.3 math-exercise semantics (verbatim)

- `check(request)`: the modes, form checks, reject rule and numeric rules of `:385-453` with `:207-244` (`.15g` half-up rounding, significant figures, tolerance).
- `check_custom(request)`: parses expressions and named matrices as `:488-502`, executes `checker` in `namespace(request)`, calls `check(response, symbols)`, normalizes.
- `namespace(request)` is a de-facto author API and is frozen: a fresh dict per call with exactly the names a `#| checker:` sees today (`dict(globals())`, `:504`) — SymPy's `from sympy import *`; `parse_expr` and the three transformations; `_math_tf`; `json` as `_mj`, `re` as `_mre`; `log10`, `floor`, `gcd` **from `math`** (they shadow SymPy's `floor` and `gcd` today, `:177`); `assess_basis`, `graph_from_response`; the private helpers under their old names; and the current request's `_math_response_json`, `_math_vars`, `_math_checker`. Names an earlier request of another kind left in the module (page history) are not reproduced. `tests/math_exercise/test_namespace.py` compares names and origins with `namespace-0.10.0.json` recorded from the legacy module.
- `authored.run_question(options, base)` = `question-tests.py:29-44` (custom checkers only; symbols from `vars`; checker and tests in one namespace; `test(check, symbols)` with the raw `check`); `main` keeps the output lines ("N authored question tests passed; M custom questions without tests.", "math-exercise question tests failed: …") and exit statuses (`:87, 90-95`).

### 2.6 Semantics switches for S-03 and S-06 (AC decides the defaults)

`ctm_checkers.stack.semantics.Semantics` (frozen): `log_root_abs ∈ {"principal" (today), "stack"}` (S-03), `decimal_ties ∈ {"exact-half-even" (today), "binary64"}` (S-06); `DEFAULT = Semantics()` keeps today's behaviour. ## 3. Packaging, delivery, versions

### 3.1 The wheel

- `tools/build.py` (stdlib only) writes the pure-Python wheel `ctm_checkers-<version>-py3-none-any.whl` from `src/` with `dist-info` (`METADATA`, `WHEEL`, `RECORD`, licence): entries sorted, timestamps 1980-01-01, fixed modes, DEFLATE.
- `--check` (CI, umbrella builder) compares the committed wheel's **contents** (file list, bytes, metadata) with `src/`, checks that `ctm-checkers.js` embeds exactly the committed wheel (sha256) and that `checkers.json`, `_extension.yml`, `pyproject.toml` and `__init__.py` agree on version and API. Contents, not compressed bytes: zlib builds (zlib, zlib-ng) produce different DEFLATE streams, so bit-identical rebuilding across machines is not a requirement; the sha256 of the committed wheel identifies what runs in build and browser.
- CI checks that the wheel installs with pip and imports.
- Size (§0.1): about 56 KB, 75 KB as base64.

### 3.2 The generated extension folder

**Why a folder of its own in ctm-checkers, not a ctm-libs resource** (audit §5.1 proposed a ctm-libs resource): (1) the umbrella copies the extension folders of pinned repositories (`setup-feedback-integration.py:359-367`), so it pins ctm-checkers like the other components; (2) a checker release (STACK fixes, B rows) needs no ctm-libs release; (3) pyodide-interaktiv will ship a copy of ctm-libs for its standalone users (step 3, P14) and should not carry a grader it never uses; (4) no vendored binary with provenance in a second repository.

Quarto refuses an extension that contributes nothing; a metadata contribution is accepted and is not merged into pages (§0.1). Authors never list it; it has no filter:

```yaml
title: CTM checkers
author: CTM team
version: 0.1.0
quarto-required: ">=1.8.27"
contributes:
  metadata:
    ctm-checkers:
      api: 1
```

### 3.3 Browser loading

**Decision.** A generated classic script `ctm-checkers.js` carries the wheel as base64 with its sha256, version and API level. ctm-libs registers it as HTML dependency `ctm-checkers` (head, deduplicated by name). ctm-libs' runtime installs it into a Pyodide with the two calls every runtime on the page offers — `globals.set(name, string)` and `runPythonAsync(code)` — and Python checks the sha256, writes the wheel to the interpreter's file system, puts it on `sys.path` and imports from it (zipimport).

```js
/* Generated by ctm-checkers tools/build.py; do not edit. */
(function (root) {
```

## 11. Risks

1. **The `#| checker:` namespace is a de-facto API** (a copy of a 385-line module's globals, with `math.floor`/`math.gcd` shadowing SymPy's). Splitting the module could drop or change a name silently. Mitigation: frozen name list with origins, legacy aliases, 78 custom checkers in the goldens.
2. **Protocol change** (11 + 3 globals → one JSON request): number types, booleans, the response as object instead of text. Mitigation: capture at the runtime boundary, L1 replays the exact values, L2 runs end to end.
3. **zipimport in real browsers and through pyodide-interaktiv's worker** is verified in Node only. Mitigation: T6 before U2 merges.
4. **Golden stability** (hash seed, platform messages, timing). Mitigation: double recording, per-platform outputs reported as findings, slow inputs excluded and listed.
5. **Build-time environment**: `PYTHONPATH` from Lua on Windows, authors' Python below 3.10, custom interpreters. Mitigation: T7, one clear message.
6. **Version coupling**: the umbrella release needs a tagged ctm-checkers; components' CI pinned to a ctm-checkers commit can lag `main`. Mitigation: the weekly tracker builds with ctm-checkers `main`; pin bumps are small PRs.
7. **Golden size and review load** (several MB of JSONL). Mitigation: identical requests stored once, checker sources by hash, one file per corpus, `golden.py diff` summaries.
8. **stack-sympy between steps 2 and 6** needs the package without being in it, keeps a second Pyodide in its worker (S-16) and an English UI. No users; stated in its README.
