## 2. Lua: loading ctm-libs

### 2.1 Rules for ctm-libs modules
- Paths only from `debug.getinfo(1,"S").source`. Never `quarto.utils.resolve_path` (it resolves against the *running* filter, i.e. the component) and never relative paths in `add_html_dependency` (Quarto's `resolvePathExt` resolves them against the running filter's directory; `/opt/quarto/share/pandoc/datadir/init.lua:322`).
- HTML only: APIs return neutral values for other formats; the reader subprocess never runs for PDF/DOCX.
- One instance per Pandoc run in `_G.__ctmLibs` (filters share Lua globals, as `__ctmAiFeedbackInstallation` already relies on).
- Errors: `assert(false, msg)`.

### 2.2 `lua/ctm.lua`
```lua
local dir = debug.getinfo(1, "S").source:sub(2):match("^(.*)[/\\]lua[/\\][^/\\]+$")
local function manifestVersion(d)
  local f = io.open(pandoc.path.join({d, "_extension.yml"}), "r")
  local v = f and f:read("*a"):match("\nversion:%s*['\"]?([%w%.%-]+)") or "unknown"
  if f then f:close() end
  return v
end
local cached = _G.__ctmLibs
if cached then
  if pandoc.path.normalize(cached.dir) ~= pandoc.path.normalize(dir) and cached.version ~= manifestVersion(dir) then
    assert(false, "This page combines two CTM installations: " .. cached.dir .. " (" .. cached.version .. ") and "
      .. dir .. " (" .. manifestVersion(dir) .. "). List only ctm-assessment in filters, or remove the separately added copy.")
  end
  return cached
end
local ctm = {dir = dir, version = manifestVersion(dir), api = 1}
setmetatable(ctm, {__index = function(self, name)       -- settings, locale, deps, runtime, feedback, policy
  local path = pandoc.path.join({dir, "lua", name .. ".lua"})
  local f = io.open(path, "r"); if not f then return nil end; f:close()
  local module = dofile(path)(self); rawset(self, name, module); return module
end})
function ctm.filters()
  return {
    {Meta = function(meta) ctm.settings.load(meta); return ctm.feedback.bridge(meta) end},
    {Callout = function(c) return ctm.feedback.markCallout(c) end},
    {Pandoc = function(doc) return ctm.feedback.prepare(doc) end},
  }
end
_G.__ctmLibs = ctm
return ctm
```

### 2.3 Component bootstrap `ctm-bootstrap.lua` (byte-identical in math-exercise and py-exercise)
```lua
-- CTM bootstrap: byte-identical in every CTM component (the package build checks it).
-- Finds ctm-libs, the internal library of CTM Assessment, and returns the page's instance.
local INSTALL = "quarto add https://erasmus-ctm.github.io/ctm-assessment/ctm-assessment.tar.gz"
local API = 1
local function exists(p) local f = p and io.open(p, "r"); if f then f:close() return true end return false end
local function candidates()
  local list = {}
  -- 1. Next to this component: the package (_extensions/ctm-libs) or one owner folder.
  local root = debug.getinfo(1, "S").source:sub(2):match("^(.*)[/\\][^/\\]+[/\\][^/\\]+$")
  if root then list[#list + 1] = pandoc.path.join({root, "ctm-libs"}) end
  -- 2. The project's _extensions (nearest one for a single file), with owner folders.
  local base = quarto.project.directory or pandoc.path.directory(quarto.doc.input_file)
  while base and base ~= "" do
    local ext = pandoc.path.join({base, "_extensions"})
    list[#list + 1] = pandoc.path.join({ext, "ctm-libs"})
    local ok, owners = pcall(pandoc.system.list_directory, ext)
    if ok then for _, o in ipairs(owners) do list[#list + 1] = pandoc.path.join({ext, o, "ctm-libs"}) end end
    if quarto.project.directory then break end
    local parent = pandoc.path.directory(base); if parent == base then break end; base = parent
  end
  return list
end
return function(component)
  for _, dir in ipairs(candidates()) do
    local entry = pandoc.path.join({dir, "lua", "ctm.lua"})
    if exists(entry) then
      local ctm = dofile(entry)
      assert(ctm.api >= API, component .. " needs a newer ctm-libs than " .. dir .. ". Update CTM Assessment: " .. INSTALL)
      return ctm
    end
  end
  assert(false, component .. " is part of CTM Assessment and needs its library ctm-libs, which is not installed. Install CTM Assessment: " .. INSTALL)
end
```
Use: `local ctm = dofile(quarto.utils.resolve_path("ctm-bootstrap.lua"))("math-exercise")`.

Why a per-component file is unavoidable (decision 10 exception): Quarto has no dependency mechanism between extensions; a filter reaches files only through its own path; components must also work when listed individually (documented: `filters: [jsxgraph, math-exercise]`) and in their own dev builds, and must stop with the install command *before* anything from ctm-libs can be loaded. The file contains location logic only; everything else lives in ctm-libs. Sibling-first keeps F-46's rule ("the installation next to each consumer wins").

Where it finds ctm-libs:
- package: `_extensions/ctm-libs` next to `_extensions/math-exercise` (sibling);
- `quarto add Erasmus-CTM/ctm-libs` (or `…/ai-feedback`): `_extensions/Erasmus-CTM/ctm-libs` (project scan);
- component CI: `quarto add ./_ctm-libs-source --no-prompt` installs `_extensions/ctm-libs` and the alias (Quarto copies every extension of a source: quarto.js `readAndCopyExtensions`);
- missing: render stops with the install command (decision 3).
Check: the umbrella builder compares the sha256 of `math-exercise/ctm-bootstrap.lua`, `py-exercise/ctm-bootstrap.lua` and ctm-libs `bootstrap/ctm-bootstrap.lua` (replaces the `shared_copies` entries at `scripts/setup-feedback-integration.py:240-247`).

## 3. Settings

### 3.1 Reader `read-settings.ts` (one `quarto run` per page, cached in `ctm.settings`)
Input (stdin; never the command line, F-56):
```json
{"projectDirectory": "...|null", "inputFile": "...", "profiles": ["no-ai"],
 "sections": ["ai-feedback", "ctm-assessment", "math-exercise", "py-exercise"],
 "documentMeta": {"<section>": {"<key>": "<JSON value>"}}}
```
`documentMeta` = Quarto's merged `doc.meta[section]` converted by Lua: MetaBool → bool, MetaString/Inlines/Blocks → string (math kept as `\(…\)`, as `feedback-policy.lua:5-17` does), MetaList → array, MetaMap → object (today only scalars are passed, l.50-56).

Levels (Quarto's order, as today l.41-53): `_quarto.yml|yaml` → `_quarto-<profile>.yml` in reverse listed order (first listed wins) → `_quarto.yml.local|yaml.local` → `_metadata.yml` from project root to the page directory → page front matter. Each level keeps its own values per section (no `Object.assign`), so additive and AND keys can be computed. A non-mapping section is an error (as l.29).

Output (stdout):
```json
{"settings": {"<section>": {"<key>": {"value": "<JSON>", "origin": "_quarto.yml|pages/x.qmd|document metadata"}}},
 "policies": "<JSON string {layers, pageLayers, projectPolicy, pagePolicy}>", "policyNames": ["..."],
 "warnings": ["..."], "errors": ["..."]}
```
Policies are always read and validated with `feedback/feedback-core.js` (`resolvePolicy` for the four integrations, as l.140-143), also when feedback is disabled, so both builds fail identically. Only emission depends on P22.

Exceptions: `ai-feedback.enabled` = AND over every file level, document metadata and `CTM_FEEDBACK` (any level can turn feedback off, none can turn it back on); policy keys are read from file levels only (as today) with the A2 rules.

## 4. Locale

### 4.1 Resolver (Lua `lua/locale.lua`, JS `locales/ctm-locale.js`)
- `normalize(tag)`: lowercase, `_` → `-`, primary subtag; `no` → `nb`.
- `chain(tag)`: `[primary]`, then `nb` after `nn`, then `en` (`nb-NO` → nb,en; `no` → nb,en; `nn` → nn,nb,en; `de-CH` → de,en; `sv` → sv,en).
- Language for a component: first source set among component option (`math-exercise: lang`, `py-exercise: lang`; for the feedback UI `ai-feedback: ui-language`) → `ctm-assessment: lang` → Quarto `lang` → `en`; then the first language of its chain that the namespace supports. Activities: `uiLanguage` from this resolver; `feedbackLanguage` stays the raw tag (`feedback-language` attribute → `ai-feedback: feedback-language` → `ctm-assessment: lang` → Quarto `lang`).
- Lua: `ctm.locale.resolve(component) -> lang, tag, origin`; `ctm.locale.text(ns, key, lang, ...)`; `ctm.locale.use(ns)` (registers `ctm-locale` + `ctm-locale-<ns>`); `ctm.locale.supported(ns)`. Missing key → English + one `quarto.log.warning`.

### 4.2 Catalogue format (`locales/<ns>.js`; valid JS, payload strict JSON between markers)
```js
/* CTM Assessment message catalogue: math-exercise. Edit the JSON only (scripts/check-locales.py). */
CTMLocales.add("math-exercise",
/*BEGIN-JSON*/
{"$languages": ["en", "de", "nb"],
 "en": {"checkButton": "Check",
        "resPartial": {"$t": "Partially correct ({pct}%).", "$args": ["pct"]},
        "stop": {"$ref": "common.stop"},
        "resNotForm": {"$t": "Mathematically correct, but not written in {form}. Rewrite the expression accordingly.", "$args": ["form"], "$lookup": {"form": "formNames"}},
        "formNames": {"factored": "factored form", "expanded": "expanded form", "single_fraction": "a single fraction", "lowest_terms": "lowest terms", "*": "the required form"},
        "legend": [["x^2", "x^2 \\text{ or } x{**}2", "Power"]]},
 "de": {"…": "…"}, "nb": {"…": "…"}}
/*END-JSON*/
);
```
Entry kinds: string (verbatim, may contain HTML); data (arrays/objects without `$` keys, verbatim); `$ref` (`<ns>.<key>`, same language); `$t` + `$args` (function of positional args); plural `{"$args": ["p","t"], "$plural": "t", "one": "…", "other": "…"}`; `$lookup` (arg mapped through a data entry with `"*"` default). Python `{}` templates (py-exercise `msg*`) stay plain strings. Lua and Python read the JSON between the markers; the browser runs the file. Compiled tables keep today's call sites (`L.resPartial(pct)`).

## 5. Feedback module (`lua/feedback.lua`)

### 5.1 P22: build without AI feedback
- Switch: disabled when `os.getenv("CTM_FEEDBACK") == "off"` or `ai-feedback.enabled` resolves to false (AND rule). Other non-empty `CTM_FEEDBACK` values except `on` → warning. Reason string names the origin (e.g. `ai-feedback: enabled: false (_quarto-no-ai.yml)`).
- API: `ctm.feedback.enabled() -> bool, reason`; `ctm.feedback.request(component, wanted, origin) -> bool` (returns `wanted and enabled`; when disabled, prints one build message per page: "AI feedback is off for this build (<reason>); left out on this page: <items>". Never an error).

### 5.2 A5: explicit context also sends the section prose
- Walk state entries become `{text, from}` (`from` = ids of enclosing context blocks; `isContext(b)` with an identifier pushes it while walking its content, today l.137-138).

### 12.1 Amendment: stacked sets (AC, 20 Oct 2026; binding)

AC approved a second merge protocol for sets of pull requests across
repositories. Later steps refer to this section. For a set prepared this way,
it replaces "push a commit without trailer, then merge", the re-pin commit
("Pin the merged components") and "trailers only in head commits":

1. **Prepared fully in advance.** Each pull request of the set pins its
   dependencies at the exact reviewed head commits of the other pull requests
   (`integration/feedback/repos.json`, a component's `.github/pins.json`,
   pyodide-interaktiv's `.github/ctm-libs-source.json` and shipped copy),
   not at merge commits, and no head commit carries a `CTM-Review-Refs`
   trailer. Copies that must be byte-identical (the bootstrap, the shipped
   ctm-libs) come from the dependency's head.
2. **Up to date.** Every branch contains its base (merge the base in, never
   rebase), so the merge commit's tree equals the head's tree and the head
   becomes part of `main`'s history when it merges: the pins stay valid
   without a commit after the merge.
3. **One combined CI run** tests the whole set at exactly those commits
   before it goes to AC: the umbrella's build and tests, the course
   comparisons and the browser checks (the umbrella pull request's CI, which
   builds every pinned head).
4. **One sitting.** AC merges the set in the stated order, with merge
   commits only, and no pin commits between the merges. For each merge:
   - before: the pull request's head is the reviewed SHA the set pins
     (`gh pr view N --json headRefOid`), and it is not behind its base
     (`git rev-list --count HEAD..origin/<base>` on the head is 0);
   - after: the merge commit's tree is the head's tree
     (`git rev-parse <merge>^{tree}` equals `git rev-parse <head>^{tree}`).
   If one of them fails, stop the sitting: the set is checked again
   (item 5).
5. **If `main` moves** under any pull request of the set before AC merges,
   the set is checked again (brought up to date, pins and copies moved to
   the new heads) and the combined CI runs again.
6. **Afterwards**, main's pins must resolve to commits on each dependency's
   main: `python scripts/setup-feedback-integration.py --check-pins` (a pin
   that `repos.json` marks with `pin-outside-branch`, the JSXGraph fork
   commit, is skipped). It cannot see a base that moved before a merge: the
   head is still an ancestor; item 4's tree check does.
