Invariants for every PR:

1. **The courses are frozen until they migrate.**
   - Before anything of step 4 merges into ctm-assessment `main`, each course pins ctm-assessment to its current commit (PR P0; for ingmat3a also on `linalg-branch`).
   - Nothing of step 4 reaches their learners until the course's own migration PR. That PR sets `ref:` back to `main` in its **first** commit (pull-request builds do not publish), so every commit's CI builds the new package. The old-against-new browser check (§6.3) runs on the PR head, and the PR merges only after it passes.
   - Other users who follow `main` get exactly the behaviour changes AC decided: tab links on and saving on, both listed in the CHANGELOG. Pages without the new syntax are otherwise rendered as before. The umbrella example site's comparison may differ only in the categories of `expect/step4.yml` (§6.2).
2. **No HTML in Markdown.** Every feature is plain Pandoc/Quarto Markdown: fenced divs with classes and attributes, empty fenced divs as markers, heading attributes, YAML options.
3. **No grade changes.** Restoring an answer never runs Python and never re-checks it.
4. **Saved answers stay in the learner's browser.**
   - Saving is on by default (AC).
   - An author turns it off with `save: none`. The docs recommend this for exam, test and shared-computer pages.
   - A learner turns it off per course, which deletes their saved answers. A course-wide "delete all my answers" is always offered.
   - There is no automatic expiry, and nothing is ever sent anywhere.
5. **Builds stay clean.** ingmat3a and ctm-demo build green, with no new warnings, from the latest ctm-assessment `main` once they follow it again. Merge commits only.

### 1.4 Quarto facts that constrain the syntax
1. **Tab headings lose their id and attributes before user filters.** The Tabset node carries only the title. Extensions cannot declare `at: pre-ast` (schema error in `_extension.yml`). A **project-level** `filters: - {path: …, at: pre-ast}` sees the heading attributes and can keep them.

   Verified in `ingverify/`: a 25-line `tab-ids.lua` that moves each tab heading's id and attributes onto an empty div at the start of its pane makes all four dead links of §1.2 work. Load and click were tested with today's `tab-links.html`: each target sits in the active pane, in the right tab.
2. **`.solution` is taken.** Quarto turns `::: {.solution}` into its Proof node before user filters. A filter's `Proof` handler sees `type == "Solution"` and the `title` attribute.
3. **A reveal shows everything without the filter.** Without step 4's filter, `::: {.reading-step}` renders as an always-open div. With `.solution` it renders as Quarto's visible "*Solution.*".
4. **Empty anchors work.** `::: {#x}` + `:::` gives `<div id="x"></div>`.
5. **A heading inside raw `<details>` breaks the page.** Pandoc's section divs swallow `</details>`: in today's flat shape the heading and what follows escape the `<details>`. Inside a wrapping Div the HTML is mis-nested. The fix is verified (review `q5/b.qmd`): `<details><summary>` as raw blocks, then a **Div holding the content**, then `</details>`.
6. **The summary is a `Para` in list items.** Pandoc's AST for flat `<details>` is `RawBlock`, `RawBlock <summary>`, `Plain` title, `RawBlock </summary>`, the content, `RawBlock </details>`; inside a list item the title is a `Para`. The AI-context walk treats the raw open and close tags as a closed scope (`ctm-libs/lua/feedback.lua:319-363`).
7. **Pandoc applies backslash escapes in attribute values.** `title="$\mathbf{A}\,x$"` loses `\,`.
8. **Chromium opens a closed `<details>` on fragment navigation by itself** (load and click; not after `pushState`). Chromium-only tests therefore hide a broken script.
9. **Grouped tabsets override a deep link.** Quarto's grouped tabsets (`group=`) re-apply the stored group on `pageshow`, after other scripts have opened a tab, so a deep link loses (review `group.cjs`). Neither course uses `group=`.
10. **The site root is known at runtime.** Website pages carry `<meta name="quarto:offset">`; single files do not. GitHub Pages serves `/p/x.html` and `/p/x`, and `/` and `/index.html`.

## 2. Target behaviour and authoring syntax

### 2.1 Reveals (P18, F1)

```markdown
::: {.reading-step title="Gå i dybden: skaler uten å dreie"}
…any Markdown, including headings, maths, code cells, exercises…
:::

::: {.solution}
…
:::

::: {.hint title="Hint for A"}
…
:::

::: {.details title="SciPy-oppslag: kall og resultat"}
…
:::
```

- **Four classes.**
  - `.reading-step`: follows the modes.
  - `.hint`, `.solution`, `.details`: closed, never touched by the modes.
- **Title.** `title` is inline Markdown. Pandoc applies backslash escapes in attribute values (§1.4 item 7), so a TeX backslash is written twice (`$\\mathbf{A}$`). The docs show this, and the converter doubles backslashes (no current title has one).
- **Default titles** when `title` is absent:

  | | nb | nn | en | de |
  |---|---|---|---|---|
  | `.reading-step` | "Gå i dybden" | "Gå i djupna" | "Go deeper" | "Vertiefung" |
  | `.solution` | "Løsningsforslag" | "Løysingsforslag" | "Solution" | "Lösungsvorschlag" |
  | `.hint` | "Hint" | "Hint" | "Hint" | "Hinweis" |

  `.details` has no default: a missing title stops the render, naming the file and line.
- **`.solution`.** Quarto's `name="…"` is accepted as an alias of `title`. The block is taken over in the `Proof` handler for HTML only; PDF and other formats keep Quarto's Solution environment. Other classes in other formats become the title in bold followed by the content, open.
- **HTML output** (§1.4 items 5–6). As the first pass of the ctm-libs filter, before AI-feedback preparation, a reveal becomes:
  1. `RawBlock <details class="ctm-reveal <class>">`
  2. `RawBlock <summary>`
  3. the title (`Plain`)
  4. `RawBlock </summary>`
  5. `Div.ctm-reveal-body[content]`
  6. `RawBlock </details>`

  Consequences:
  - Headings inside a reveal stay inside it, and the content after it stays in place.
  - The AI-context walk still meets the same raw open and close tags around the content, so contexts are unchanged. A byte-identical test, which includes a heading fixture, proves it (§6.1).
  - Compared with today's DOM, the `class` attribute changes and one wrapper `div` is added.
- **Look.** The CSS lives in ctm-libs (`ui/ctm-ui.css`), with colours as custom properties (`--ctm-reveal-*`) and a `.quarto-dark` set.
  - `.reading-step` and `.hint`: ingmat3a's box (left border 3px `#7899ac`, background `#f6f8fa`, padding .7rem 1rem).
  - `.solution`: green (`#4f7d57`/`#f4f8f4`).
  - **`.details`:** related but clearly distinct, since it does not follow the switch: the same padding and radius, a **dashed** 2px left border `#9aaebc`, a transparent background, and a summary in normal weight with a "›" marker. A3/A4's screenshots show it in reading mode next to an open reading step.
  - Summaries of reveals: bold, with a 3px `#ad6600` `:focus-visible` ring.
  - The courses **keep** their generic `details > summary` rules (§1.3), which also style component-generated `<details>`.
- **Script `ui/ctm-reveal.js`:**
  - a `#hash` target opens **every** closed `<details>` around it (as today, so component-generated ones too);
  - `beforeprint` opens the reading steps and `afterprint` restores them;
  - `toggle` events are coalesced into one `resize` per animation frame.
- **Accessibility.** Native `<details>`/`<summary>`: Tab, Enter and Space work, and the expanded state is announced without ARIA.

### 2.3 Links into tabs (AC: on by default; tab-title ids)
- **Tab ids are kept by a project-level pre-ast filter** (AC 19 Oct). ctm-assessment ships `_extensions/ctm-assessment/tab-ids.lua`, and a course adds one entry to `_quarto.yml` in its migration PR:
  ```yaml
  filters:
    - path: _extensions/ctm-assessment/tab-ids.lua
      at: pre-ast
    - ctm-assessment
  ```
  - For each `.panel-tabset`, every tab heading's id (explicit or automatic) and attributes move onto an empty `<div id class="ctm-tab-target">` as the first block of its pane. The tab level is the first top-level heading, as in Quarto's `parse_tabset_contents`.
  - **Crossref-prefixed ids are skipped**, with one warning each. Quarto would otherwise turn the moved div into a float or theorem: `## Plot {#fig-plot}` gives an empty "Figure 1" (review R2-4). The prefixes come from Quarto's crossref categories (`fig- tbl- lst- thm- lem- cor- prp- cnj- def- exm- exr- sol- rem- eq- sec-` and any custom category), so the id stays dead, as without the filter.
  - A `Meta` function sets `meta["ctm-tab-ids"]` for `markdown-lint`.
  - **It is the fail-safe against an older package.** With a package that lacks the file, Quarto stops with `cannot open _extensions/ctm-assessment/tab-ids.lua` (verified, R2-7). Every migrated course therefore adds the line, even without tabsets.
  - `## 3.5 Polynomer {#uke3-del5}` and `quiz=` (§2.6) then work on tab headings.
  - Without the line, Quarto's behaviour is unchanged and the ids stay dead (documented). With `markdown-lint: true` (§2.8) a page with a tabset warns that the line is missing.
  - The code lives in ctm-assessment, because that is the file authors reference (P20: they never name ctm-libs). It is a single, standalone 25-line file, so nothing is duplicated.
- **Anchors:** `::: {#id}` + `:::`. The converter keeps all 72 anchors as empty divs; it does not move them onto tab headings (less churn, and they need no filter). Tab-heading ids are for tabs that have no anchor, and for the four links of §1.2.
- **Tab links:** `ui/ctm-nav.js`, the courses' `tab-links.html` moved into ctm-libs, on **by default** on every page with a tabset (AC). `ctm-assessment: tab-links: false` turns it off.
  - **Opening:** every enclosing tab, nested ones too, and every enclosing `<details>`.
  - **Where it reacts:** in-page links, links from other pages, load, Back/Forward.
  - **Order:** its initial navigation runs after Quarto's `pageshow` handler (grouped tabsets, §1.4 item 9) and after `quarto-nav.js`'s `hashchange` offset scroll. It re-checks on the next frame that the target pane is still active. A **deep link wins over a stored group choice** for that view and does not change the stored choice.
  - **Scroll:** the target lands below the header. While Monaco, JSXGraph or Pyodide output change the layout above it, a `ResizeObserver` keeps it pinned for up to 2 s, or until the user scrolls, types or clicks.
  - **Focus:**
    - **a deep link to a tab title** (a `.ctm-tab-target`) scrolls so that the tabset's `.nav-tabs` row and the pane's start are below the header. It focuses the **tab panel** (`role=tabpanel`, `tabindex=-1` while focused), or the pane's first heading when there is one, and never an off-screen tab button;
    - any other target gets `tabindex="-1"` if it is not focusable (removed again on blur) and `focus({preventScroll: true})`;
    - `:focus:not(:focus-visible)` draws no ring for mouse users.
  - **API:** `CTMNav.reveal(element)`, which the progress panel uses.
  - The address bar shows the target's id.

### 2.5 Saved answers (P17; AC: on by default)
- **Default `save: answers`** for every component.
  - Authors turn it off with `ctm-assessment: save: none` (project or page), a component spelling (`py-exercise: save: none`), or `#| save: false` on an exercise.
  - The docs recommend `save: none` for exam, test and shared-computer pages.
- **pyodide-interaktiv cells** are covered only after step 3 (PR B6). Until then they keep their current opt-in saving (`pyodide: local-storage`).
- **Labels.** An exercise without a label, or with a label that is not unique on the page, is **not saved**. It gets one build warning per page listing them, and never stops the render. Unlabelled pyodide cells (B6) are keyed `cell:<hash>`.
- **Page bar.** On a page that saves, a static region at the top (below the switch) says "Svarene dine lagres bare i denne nettleseren." It is not announced on load; changes go to a separate `aria-live` status. It offers three actions:
  - **"Slett svarene på denne siden"**;
  - **"Slett alle svarene dine i dette emnet"** (course-wide; confirms);
  - **"Ikke lagre på denne enheten"**: confirms "Dette sletter alle lagrede svar i dette emnet og slutter å lagre", then deletes every record and the seed of the course and stores `~prefs.save=false`. "Lagre igjen" turns it back on.

  An old `qpyodide:local-storage-user-disabled=1` sets the switch to off once, without deleting anything. This is intentional: under the old opt-out nothing was saved, so there is nothing to delete. The "off deletes" rule applies only when the learner turns saving off in the page bar.
- **No automatic expiry.**
- **The learner seed.** It is a random identifier that never leaves the browser (docs). It follows the switch: `localStorage` when saving, `sessionStorage` otherwise.
- **Restore.**
  - Inputs are filled. Python is never run and nothing is re-checked.
  - A saved result is shown greyed ("Sist sjekket 20.10.: delvis riktig (50 %)") until the next Check.
- **Exercise without variants.** The record's `source` (16 hex of the SHA-1 of the block text, from the build) must equal the current one.
  - Otherwise the answer is **offered**, not filled ("Oppgaven er endret siden du svarte. Vis svaret ditt?").
  - The last result and the progress tile are then shown as outdated.
- **Exercise with variants or a pool** (decision 9 with the B2 amendment):
  1. **Hash match among the deployed variants:** the variant is restored exactly with its answers.
  2. **No hash match, but `n` (then `id`) matches:** the variant has **changed**. One line says so ("Denne varianten er endret"). The old answers are shown read-only, not as inputs. The current version of variant `n` is shown with empty fields, and "New variant" stays available.
  3. **No match:** the variant was withdrawn. One line says so, the old answers are read-only, and a new variant is offered from the cycle.
  4. In cases 2 and 3 the last result and the tile are outdated.
  5. "New variant" (decision 10, owned by `variants.js`) confirms when fields are filled and then replaces the answers (one record per exercise). The new `n` is added to `seen`. Without saving, the choice lasts for the session.
- **Clean-up.**
  - When a page loads, the store deletes this page's records whose id is not in the page's build manifest: removed exercises and edited unlabelled cells.
  - Records over 64 KB are not written (one message).
  - Quota and `SecurityError` fall back to memory with one message.
- **Not restored in step 4:** graphical (JSXGraph) answers.

### 2.6 Progress and quizzes (P17)
- **Page progress:** `ctm-assessment: progress: true`. The panel is built from the build-time manifest, so it is there before Python loads.
- **A quiz starts at either of:**
  - a heading with `quiz=<id>`: `## 1.2 Binære tall {quiz=m1-2}` (needs the pre-ast line for tab headings, §2.3);
  - an empty marker `::: {.quiz #m1-2}` + `:::`.

  It covers the rest of that section: the tab, or the heading section, including nested tabs and subsections. The default title is the tab or heading text. The panel sits at the start of the section. Exercises outside quizzes form the page panel.
- **Render errors:** a quiz without exercises; a duplicate quiz id; a quiz start inside a reveal.
- **The panel** is an ordered list of tile buttons.
  - Each tile shows a status as text and icon ("✓ riktig", "½ delvis", "✗ feil", "– ikke prøvd"), with an `aria-label` such as "Oppgave 3: delvis riktig".
  - The total reads "2,5 av 5".
  - A click calls `CTMNav.reveal` and focuses the exercise.
- **Results.** Components emit `ctm:result` `{component, id, score 0–1, status: correct|partial|wrong|invalid, variant}`. `invalid` does not count as an attempt. pyodide cells are not listed.

## 3. Storage

### 3.1 Keys (versioned)
```
ctm|1|<course>|<page>|<exercise id>   record                      localStorage (saving on)
ctm|1|<course>|~prefs                 {"v":1,"save":false}        localStorage
ctm|1|<course>|~seed                  random 128-bit hex          local when saving, else session
ctm|1|<course>|~mode                  "lecture" | "reading"      sessionStorage
```
- `<course>` is the `storage-key`, otherwise the site root path from `quarto:offset` (`/ingmat3a_ntnu/`, which separates `/ingmat3a_ntnu/linalg/`), otherwise the page directory for single files.
- `<page>` is the path from the root with `.html` dropped. `/` and `…/` map to `…/index`, so `x`, `x.html`, `/` and `/index.html` give the same key.
- `<exercise id>` is the label, or `cell:<hash>[:n]` for an unlabelled pyodide cell (B6).
- Parts are escaped with `encodeURIComponent`.
- Variants V2 uses exactly these keys and the record below.

### 3.2 Record (at most 64 KB)
```json
{"v": 1, "component": "math-exercise", "saved": "2026-10-20T10:31:00Z",
 "source": "a1b2c3d4e5f60718",
 "variant": {"n": 7, "id": "p1=2 p2=-1 x0=1", "hash": "7380452c28c64da4"}, "seen": [3, 7],
 "inputs": {"fields": {"u derivert": "1"}},
 "result": {"score": 0.5, "status": "partial", "at": "2026-10-20T10:30:12Z"}}
```
- A record holds either `source` or `variant` + `seen`.
- `inputs` belong to the component:
  - math-exercise: fields by label (decision 13), otherwise by field id, plus matrix sizes;
  - code: `{"code": "…"}`.
- A record with an unknown higher `v` is kept untouched.

### 3.3 Migration of existing keys (lazy, when saving is on for that exercise)
| Old | New | Rule |
|---|---|---|
| `pyex|<path>|<label>` | `…|<page>|<label>`, `inputs.code` | see the rules below the table |
| `qpyodide:code:…:label:<l>` / `:hash:<h>[:n]` | `…|<l>` / `…|cell:<h>[:n]` | B6; older epochs ignored, as today; migrated keys deleted |
| `qpyodide:local-storage-user-disabled` | `~prefs.save=false` once | old key kept (other sites share the origin) |
| `learning-mode` | — | not migrated (cut: at most one tab starts in lecture mode once) |
| `math-pool|…` | — | variants V2 |

**`pyex` rules:**
- **Paths looked up:** the current `location.pathname` plus its variants: with and without `.html`, and for an index page `…/`, `…/index` and `…/index.html`.
- **One old key:** it is imported (`source` = current, filled as today) and every variant key is then deleted.
- **Several old keys:** the one equal to the current pathname wins, otherwise the `.html` form.
- **A new record and an old key both exist:** the old key was written after the migration by an older cached page, so it is newer. It is imported and deleted.
- **Learner switch off:** nothing is imported or deleted.
- **Reset:** it cancels the pending debounce, suppresses the change event caused by `setValue(starter)`, and deletes the record. A save whose code equals the starter deletes the record instead of writing it.

The adapters own the legacy formats (`register({legacy: [...]})`); the store knows no component.

## P1: no copy of ctm-libs' rules in the converter (AC's decision, 20 Oct)

  - Which lines are Markdown and which constructs `--check` and the baseline count come from ctm-libs. The tool builds only the baseline keys from them (classes, title, id, src).
