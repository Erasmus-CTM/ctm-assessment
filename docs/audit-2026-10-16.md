## Findings and corrections

1. **Source panels and starting drafts.** The 98 published math-exercise cells
   and eight combined-site mathematics cells had matching labels, checker code,
   check modes, answer keys and pool tasks. The combined page nevertheless
   prefilled eight activities using scripts absent from their source panels.
   The displayed draft (for example 40) could differ from the correct answer
   (42), while copying the source produced an empty field. The shared
   `examples/math-drafts.js` initializer is now used by the page and included
   verbatim in each affected source panel. A regression executes copied setup
   independently of the example page containers. Generated-variant examples
   brought in by the integration now also expose their authored source.

2. **Monotonicity.** An expression with a pole inside the interval could pass
   derivative/endpoint checks. The example now specifies continuously
   differentiable real functions and verifies the required domain and continuity.
   The counterexample `x - 1/(100*(x-1/2))` is rejected.

3. **Quadratic roots and numerical constructions.** The root exercise could
   treat variable expressions such as `-x` and `x/2` as roots of `x^2`.
   Require finite numeric constant roots and numeric monic coefficients.
   Pythagorean and Newton examples now reject non-real/non-finite inputs;
   Newton checks also avoid division by zero.

4. **Antiderivatives and expression form.** A fixed-answer comparison rejected
   valid additive constants in an antiderivative. Check the derivative/residual
   instead. The expansion example now requires expanded form. Numeric rounding
   documentation clarifies that comparison does not enforce typed digit counts.

5. **Dynamic matrices.** The five real basis examples now explicitly require
   finite real coordinates. Point-row examples reject non-real values and
   mathematically equivalent duplicate points, not just textually identical rows.
   Tests include alternative/reordered bases, incomplete/dependent sets and
   empty matrices.

6. **Graphical checkers.** Three region checkers could award full marks to empty
   or truncated coordinate arrays through `zip` and `all([])`. Require exact
   response lengths and finite coordinates. The period window now submits the
   same clamped width that it displays. Freehand monotonicity now checks the
   fitted polynomial's derivative at endpoints and isolated critical points,
   rather than only 200 sampled secants. A narrow negative derivative between
   sample points is covered by a regression. The documented numerical slope
   tolerance is 0.001.

7. **Graph theory.** No mathematical defect was found in the four construction
   checkers. Added author-owned fixtures for trees/cycles/disconnected graphs,
   Euler circuits, bipartite graphs, K5, K3,3, planar examples and malformed edges.
   Graph JSON exercises the actual shared conversion and NetworkX checkers.

8. **Python greeting.** The published prompt required printing and returning,
   but accepted a silent return-only function. Its authored checks now capture
   stdout and require exactly one greeting line. A regression challenges the
   checks with correct, silent, print-only and double-print implementations.

9. **STACK teaching copies.** `AlgMap-1-5` and `AlgMap-6-4` stated the false rule
   `c^a+c^b=c^(a+b)`; their corrected feedback uses multiplication.
   `AlgMap-2-5` awarded any reduced fraction full credit before checking its
   value. A corrected response tree checks equivalence first. The gallery
   labels these attributed CC BY-SA derivatives, shows the XML actually used,
   and links both corrected and original files. Original imports, checksums and
   compatibility replay baselines remain unchanged.

10. **Stale combined revisions.** The combined-site manifest referred to old
    component commits and deleted scoped-policy branches. It now uses current
    ai-feedback main, the resolved math integration plus this audit, the corrected
    Python example and the latest shared-feedback Pyodide revision. External
    dependencies remain pinned by full commit for reproducibility.

## Authored testing design

The optional `tests: |` and `tests: path/to/file.py` formats live with ordinary
custom-checker exercises. Both define `test(check, symbols)` and use the same
runner shipped by math-exercise. Quarto runs the assertions when rendering an
exercise that declares them; the direct command can run from VS Code or CI.
Failures identify the exercise and fail the command. Exercises without a test
block preserve their old build requirements. Generated parameter variants
retain their existing YAML fixture-list tests.

All 33 custom checker blocks in the split and legacy examples, plus seven
complete exercise blocks in the Markdown guides, have assertion coverage. Long graph/basis fixtures are in `_includes/tests`; short assertions
remain inline. Referenced files are also visible in a nested source disclosure.
See the math-exercise question-test and browser-test guides for authoring and
commands.

A separate Playwright suite uses standard `.spec.mjs` files. Shared interactions
live in `tests/browser`; exercise-specific scenarios may live beside native
fixtures in `_includes/tests/*.browser.spec.mjs`. Its GitHub action renders the
site and runs actual pointer interactions on relevant pushes/PRs or manually.
Browser tests do not run during ordinary Quarto builds.

## Validation and limits

- Resolved integration prerequisite: 89 JavaScript tests, 14 Python variant
  tests and the complete 12-page Quarto build passed.
- Audit math branch: 91 JavaScript tests, 14 Python variant tests, 40 authored
  checker suites and the complete Quarto build passed. Render tests cover
  passing/failing inline and file assertions, absence of native Python for
  untested exercises and exclusion of tests from browser grading data.
- Combined-site unit checks and all ten integration scenarios passed after
  updating branch assertions to the manifest.
- STACK: 107 tests and 144 subtests passed, with one existing skip. Corrected
  copies replay their authored question tests over every deployed seed.
- The ten translated custom checker examples in Quarto-Tutorial were challenged
  read-only with valid and invalid responses; they passed.
- Local Chromium cannot launch in this workspace. The dedicated GitHub action
  is the authority for the four actual pointer-interaction scenarios; native
  checker tests alone do not establish browser or CPython/Pyodide parity.

The fixes are proposed through pull requests. Public deployments change only
when the corresponding branches are merged and their publishing jobs run.
